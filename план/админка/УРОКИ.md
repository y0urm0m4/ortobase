# Уроки: верстаем админку по шагам

Учебный режим: на каждом шаге сперва короткая теория, потом верстка. Идём от простого к сложному.

> Раньше планировалось PHP + БД, но проект перевели на чистый фронтенд. Этот документ отражает актуальный план.

---

## ✅ Урок 1. Страница входа (Login)

**Что построили:** `admin/login.html` — карточка по центру экрана с формой входа.

**Что освоили:**
- BT5-флекс-центрирование (`d-flex`, `align-items-center`, `justify-content-center`, `min-vh-100`)
- BT5-карточка (`.card`, `.card-body`) — зачем нужен `card-body`
- BT5-формы (`form-label`, `form-control`, `form-check`)
- Связка `for`/`id` между лейблом и инпутом — зачем
- Атрибуты `type="email"`, `type="password"`, `required`, `placeholder`, `name`, `id`
- Display-утилиты (`d-flex`, `d-lg-none`, `d-none d-md-block`)
- Поведение `<form>` по умолчанию — что происходит при submit без `action`
- Зачем атрибут `name` на инпутах и почему без него данные не отправляются
- Разница между `<button type="submit">` и `<a href="...">` стилизованной под кнопку
- Относительные пути в HTML
- Инлайн-стили — когда уместны, когда нет

## ✅ Урок 2. Светлая и тёмная тема

**Что построили:** переключатель темы (`assets/js/theme.js`) — кнопка-луна в углу.

**Что освоили:**
- CSS-переменные: объявление (`--имя: значение`), использование (`var(--имя)`)
- Архитектура тем: `base.css` (структура) + `light.css`/`dark.css` (только переменные)
- Почему имена переменных одинаковые в обеих темах
- Подключение CSS в правильном порядке (BT5 → base → тема)
- Атрибут `data-bs-theme` на `<html>` для адаптации BT5-компонентов
- Переопределение `--bs-*` переменных Bootstrap (`--bs-body-bg`, `--bs-body-color`, `--bs-border-color`, etc.)
- Антифлеш-скрипт в `<head>` — почему он нужен и где должен стоять

**JS-концепции из `theme.js`:**
- IIFE — изоляция переменных
- `document.getElementById` / `querySelector`
- Optional chaining `?.`
- OR-фоллбэк `||`
- `addEventListener('click', ...)`
- Arrow function `() => {}`
- Тернарный оператор `условие ? a : b`
- `setAttribute` / `getAttribute`
- Template literal `` `${...}` ``
- `localStorage.getItem` / `setItem`

АРХИТЕКТУРА ТЕМ (ключевой момент)
═══════════════════════════════════════════════════════════════════

Три CSS-файла:
- base.css     — структура и кастомные классы, не зависит от темы, 
                 использует var(--имя) для цветов
- light.css    — только :root { --... } со значениями светлой темы
- dark.css     — те же имена переменных, другие значения

Имена переменных в light.css и dark.css ИДЕНТИЧНЫ. Меняются только 
значения. base.css пишется один раз и не знает "светло сейчас или темно".

Переменные:
  --bg-page, --bg-card, --bg-sidebar, --bg-soft, --bg-input
  --text-main, --text-muted, --text-sidebar, --text-sidebar-muted
  --border, --border-input
  --accent (#3DA9FC), --accent-hover (#1E5F8E), --accent-active
  --success, --warning, --danger, --info

Плюс переопределяем Bootstrap-переменные:
  --bs-body-bg → var(--bg-page)
  --bs-body-color → var(--text-main)
  --bs-secondary-color → var(--text-muted)
  --bs-border-color → var(--border)
  --bs-tertiary-bg → var(--bg-soft)

И на <html> ставим data-bs-theme="light" или "dark" — Bootstrap 
сам адаптирует свои компоненты (формы, чекбоксы, инпуты).

Переключение тем через theme.js:
1. При загрузке читает localStorage.getItem('ortobase-theme')
2. Применяет тему: setAttribute на <html> + подмена href у 
   <link id="theme-css">
3. По клику на #themeToggle инвертирует и сохраняет

Антифлеш-скрипт первым в <head>, до подключения CSS:
  <script>(function(){
    const t = localStorage.getItem('ortobase-theme') || 'light';
    document.documentElement.setAttribute('data-bs-theme', t);
  })();</script>

СКЛЕЙКА PARTIALS ЧЕРЕЗ jQuery
═══════════════════════════════════════════════════════════════════

В админ-страницах есть пустые <div id="sidebar-mount"></div> и 
<div id="topbar-mount"></div>. layout.js при загрузке делает:

$(function() {
  $.when(
    $('#sidebar-mount').load('partials/sidebar.html'),
    $('#topbar-mount').load('partials/topbar.html')
  ).done(function() {
    const page = document.body.dataset.page;
    if (page) {
      $(`.nav-link[data-page="${page}"]`).addClass('active');
    }
  });
});

В сайдбаре у каждой ссылки атрибут data-page="catalog" и т.п. 
На <body> страницы стоит data-page="catalog" — этим выбирается 
активный пункт меню.

СТИЛЬ РАБОТЫ
═══════════════════════════════════════════════════════════════════

1. НЕ выдавай готовый код сразу — сначала концепция, затем студент 
   пишет сам, ты проверяешь
2. Когда студент ошибается — указывай прямо, без сглаживания
3. Когда что-то очевидно — не задавай тупые проверочные вопросы, 
   студента это раздражает
4. Если он сказал "и так понятно" или "не задрачивай" — переходи к делу
5. Закрепляй новый концепт коротким вопросом ОДИН раз, не пять
6. На "не знаю" — объясняй сам, не доказывай "ну подумай ещё"
7. Мат ок в умеренных дозах, ирония ок
8. Бить большие задачи на блоки: "Блок N из M" — у студента есть 
   ощущение прогресса
9. Когда даёшь готовый код — без комментариев в коде (студент сам 
   просил), объяснения отдельным абзацем
10. Live Server не понимает PHP — если студент случайно создаёт .php 
    файл, останавливай. Только .html
11. После каждого нового JS-скрипта — построчное объяснение того, 
    что в нём (IIFE, события, селекторы и т.д.)
